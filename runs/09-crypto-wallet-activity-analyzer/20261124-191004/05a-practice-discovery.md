## Notes

I inspected the app (seed, db, tools, analyze) and then searched Microsoft Learn docs and related Azure pages. Many of the model's prior beliefs are confirmed by Azure DocumentDB docs (env vars, TLS, singleton client, idempotent upserts for seeding, compound indexes, date bucketing via $dateToString/$dateTrunc, match-first pipeline shape, explain(), allowDiskUse, server-side aggregates, projection, retries/backoff, monitoring, vector-search tuning, CMK/Private Link/Entra ID, background index builds). The prior belief about RU/s (K14) was contradicted: Azure DocumentDB uses compute tiers and storage scaling rather than RU/s provisioning. A few prior beliefs (K02, K11, K19) are application-level or MongoDB-generic practices not explicitly documented for Azure DocumentDB; I could not find an Azure DocumentDB doc that prescribes those exact numeric settings or patterns, so I left them as prior_knowledge_only and recorded the search queries tried.
