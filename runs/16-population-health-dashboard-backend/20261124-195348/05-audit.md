# 5. Best-practice audit: 16-population-health-dashboard-backend

**Verdict: pass_with_findings** (16 followed, 6 violated, 1 not applicable)

The sample implements a FastAPI service that builds a $facet aggregation (diagnosis, age bands via $bucket, gender, region), materializes cached summaries into an aggregations_cache collection (TTL index), exposes endpoints to read and refresh cached summaries, and includes an idempotent seed script and unit tests. Verification steps (pip install, pytest, seed, live aggregation, upsert, TTL index creation, and an explain via the DocumentDB MCP explain tool) were executed and recorded. Main issues: missing env settings in .env.example, lack of retry/backoff around network calls, seed uses per-document upserts instead of batched bulk writes, no use of $setOnInsert for creation-time metadata so createdAt is overwritten on every refresh, and some index/index-shape guidance (compound indexes / pre-filters) is not followed leading to the explain showing a COLLSCAN for the current pipeline. Several decisions were made from model defaults (Python minor, scheduler frequency) without an explicit public source; these are noted as documentation gaps the product team should author. See requirement_results, practice checks, decision_reviews and doc_gaps below.
