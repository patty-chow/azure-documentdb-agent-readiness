# 5. Best-practice audit: 02-real-time-event-stream-ingestion

**Verdict: pass_with_findings** (14 followed, 1 not assessable, 4 violated, 2 not applicable)

The sample implements the core prompt requirements: a Node.js (Express) ingestion service, unordered bulk writes with configurable batching, a compound unique index for deduplication, an idempotent seed, and a change-stream consumer that enqueues simulated downstream profile-update jobs. It follows several discovered best practices (singleton MongoClient, unordered bulkWrite, idempotent seed, index creation at startup). Shortcomings: change-stream resiliency (no persisted resume tokens, no backoff/retry), limited bulk-failure handling (no selective retry of retryable errors), incomplete .env.example (missing optional tunables), no offline-capable unit tests, and no IaC for provisioning mongoClusters. Change-stream end-to-end verification timed out in this environment (watch_once.js timed out despite inserted document being present); that is documented as an open issue and is likely due to cluster/permission or resume-token handling rather than the sample's wiring. See Requirement Results, Practice Checks and Doc Gaps for details and minimal fixes to get each item to 'met'.
