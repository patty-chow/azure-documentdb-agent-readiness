## Where public sources contradict the model

### P21: Do not assume Azure DocumentDB uses the Cosmos DB 'RU' provisioning model; Azure DocumentDB uses selectable compute tiers and independently sized storage (vCores/tiers), so plan capacity by picking an appropriate cluster tier, storage and sharding approach rather than only thinking in RUs.

- **Source:** [What is Azure DocumentDB (with MongoDB compatibility)?](https://learn.microsoft.com/azure/documentdb/overview#lower-cost-than-mongodb-atlas)

### P28: Azure DocumentDB exposes MongoDB change streams as the recommended change feed mechanism for MongoDB-compatible workloads; there is not a separate Cosmos DB change-feed alternative to prefer for this API.

- **The model believed:** If the managed service exposes a platform-native change feed (e.g., Cosmos DB Change Feed), evaluate using that instead of MongoDB change streams if it offers better SLAs/availability or integrates better with Azure tooling. (knowledge of `azure_cosmos_db`)
- **The source says:** Azure DocumentDB exposes MongoDB change streams as the recommended change feed mechanism for MongoDB-compatible workloads; there is not a separate Cosmos DB change-feed alternative to prefer for this API.
- **Source:** [Change streams in Azure DocumentDB](https://learn.microsoft.com/azure/documentdb/change-streams)
