# 5. Best-practice audit: 11-visual-similarity-search-image-embeddings

**Verdict: pass_with_findings** (15 followed, 6 not applicable, 3 violated)

The sample is a working Python FastAPI app that implements CLIP-based image encoding, stores embeddings, creates a cosmosSearch vector-ivf index, and exposes a /visual-search endpoint that issues a $search/cosmosSearch aggregation. The builder seeded sample data and created the index (via PyMongo) and exercised the search path; however the live cluster returned server-side errors when running the $search aggregation from the app (the cluster complained that $search must be the initial aggregation stage, and earlier an attempt reported an 'Invalid type: expected an array type field' error). Several gallery-level expectations (pinned dependency versions, a fully complete .env.example, offline unit tests, README tuning guidance and IaC for provisioning) are partly met or missing and should be fixed before publication. Many best-practice checks are discoverable in public docs/installed skills; two important public practices contradict the builder's choice to store vectors as a BSON binary subtype: Azure DocumentDB docs expect numeric arrays or documented encodings. See findings and doc gaps below.
