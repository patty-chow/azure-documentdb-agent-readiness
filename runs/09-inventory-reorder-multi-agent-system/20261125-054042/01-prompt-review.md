## Reference requirements at risk

- The connection string and model credentials come from environment variables; none appear in the repository. Reason: skill_md specifies DOCUMENTDB_URI, but the prompt does not specify embedding/chat model credentials or the exact .env variable names for models.
- .env.example lists every setting with placeholder values. Reason: prompt doesn't request .env.example explicitly; while skill_md recommends placeholders, it doesn't enumerate all model env vars.
- The vector index dimensions match the embedding model's output. Reason: the prompt doesn't specify an embedding model; the builder must choose one and ensure dims match — not specified.
- The vector index parameters are chosen for the sample's data size, and the README says how to change them for a larger one. Reason: prompt and skills give index guidance but do not require documenting parameter choices for the sample.
- A seed script loads sample data and creates the index, and can be run twice without duplicating data. Reason: the prompt doesn't mention a seed script; local-deployment skill encourages one but does not supply it automatically.
- /search returns a clear error for an empty query and when the embedding call fails. Reason: prompt doesn't ask for a search endpoint; implementing robust error-handling for search is not implied.
- Search results include the similarity score. Reason: the prompt doesn't mention any search API nor returning similarity scores.
- Dependencies are pinned in `requirements.txt`. Reason: prompt doesn't specify dependency pinning; skills provide best-practices but won't create requirements.txt automatically.
- Unit tests run without a live cluster. Reason: prompt doesn't require tests; builder will need to mock DocumentDB to meet this but it is not specified.
- Infrastructure for the cluster is provided as code, using the Azure DocumentDB resource type. Reason: skill_md explicitly provides a live cluster and instructs not to provision another; the prompt didn't request infra-as-code, so including it is unlikely.
- The README covers what the sample shows, prerequisites, setup, run, and clean-up. Reason: prompt asks to build the sample but doesn't require a full README; builder will probably add one but it's not guaranteed.
- The sample uses the name 'Azure DocumentDB' throughout, and no former or neighbouring product name. Reason: prompt doesn't require a naming convention; the builder must be instructed to prefer this name.
