# 1. Prompt review: 09-inventory-reorder-multi-agent-system

**Verdict: sufficient_with_assumptions**

The starter prompt clearly defines the multi-agent inventory-reorder scenario, the three agents and their high-level responsibilities, and that DocumentDB is the backing store. The provided run-environment notes (skill.md) supply the live cluster connection location and database to use, so a builder can start. Several important implementation details are not specified (Python version, exact driver/package versions, LLM/embedding model selection, purchase-order document shape, explicit concurrency semantics, test/CI and packaging details). Those will be chosen by the builder unless the author clarifies them.

## Reference requirements at risk

- Launching forecast and supplier agents to run in parallel (concurrently) — the starter prompt requests multi-agent coordination but does not explicitly require/describe concurrent execution; the builder must decide concurrency semantics.
- Purchase order document must include specific fields (product identifier, quantity, supplier identifier) — prompt says write purchase orders but does not enumerate required fields or exact field names.
- End-to-end demonstration that seeds sample sales velocity and supplier lead time documents and verifies exactly one purchase order per product — prompt implies writing orders and shared memory but does not explicitly require an idempotent seed script and a verification step that enforces exactly-one-per-product.
- Model credentials and API keys come from environment variables and are listed in `.env.example` — prompt and skill.md mention reading DB URI from env, but the starter prompt does not name LLM/model env vars; the reference requires listing every setting in `.env.example`.
- Pinned dependencies in `requirements.txt` — prompt does not ask for pinned versions; installed skills recommend best practices but do not supply exact pinned requirements.
- Unit tests that run without a live cluster — prompt does not mention tests or mocks/stubs for DB access; reference requires unit tests runnable offline.
- Infrastructure-as-code for the cluster — prompt/supplied run-environment says a cluster is already provisioned and discourages provisioning new clusters; reference asks for infra as code (optional) which is not provided by the prompt.
- Seed script idempotency (seed script can be run twice without duplicating data) — prompt does not require idempotent seeds; skill guidance suggests it but not enforced by prompt.
- README covering what the sample shows, prerequisites, setup, run, and clean-up — starter prompt does not mention README content explicitly.

## Questions for the prompt author

- Which LLM/chat model and/or embedding model should the LangChain agents use (provider, model name, and whether credentials should be read from environment variables)? This will change where the code calls external APIs and what .env keys to include.
- Do you require a deterministic forecasting model (rule-based/simple statistical) implemented in the sample, or should the forecast agent call an external ML/LLM model to predict reorder quantities?
- Should the sample explicitly run the forecast and supplier agents concurrently (threads/async/tasks), or is the high-level orchestration sufficient (the orchestrator can call both agents sequentially)? The reference expects concurrent execution.
- What exact fields must every purchase order document contain (field names and types) to satisfy the acceptance criteria (e.g., product_id, quantity, supplier_id, order_status, created_at)?

## Contradictions and missing references

- The starter prompt says “Using the DocumentDB skill,” but there is no single installed skill named exactly “DocumentDB skill.” The installed skills are many `documentdb-*` skills (e.g., documentdb-driver, documentdb-local-deployment). Treat the phrase as a general instruction to use the DocumentDB-related skills rather than a single skill name.
