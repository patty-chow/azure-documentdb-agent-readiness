# 5. Best-practice audit: 08-personalized-email-campaign-builder

**Verdict: pass_with_findings** (11 violated, 5 not applicable, 9 followed, 2 not assessable)

The sample is a functioning Node.js project that fetches segment documents from Azure DocumentDB, injects purchase_history and preferences into an LLM prompt, generates subject+body (via OpenAI or a deterministic fallback), and writes campaign drafts into a campaigns collection. The build follows many Azure DocumentDB best practices (singleton MongoClient, env-driven secrets, idempotent seed upserts, index creation) but it diverges from the starter prompt in one important way (the prompt asked for a LlamaIndex-based agent that registers a tool; the builder implemented a lightweight agent without LlamaIndex/tool registration). Several best-practice checks are either missing or incomplete (retry handling, explicit OIDC guidance, projection on read, upsert for campaign writes, index-before-seed ordering, monitoring and network-hardening guidance). The MCP/agent verification tools were inconsistent with the driver's view of the cluster in this run (MCP read/write calls returned empty or were disabled for writes), and OpenAI calls are opt-in (USE_OPENAI) so automated verification uses a deterministic fallback.
