# 5. Best-practice audit: 19-insider-threat-detection-pipeline

**Verdict: pass_with_findings** (6 followed, 9 violated, 3 not assessable)

The sample is functional and demonstrates the core pipeline: synthetic activity logs are seeded, per-employee feature vectors are computed, features are sent to an OpenAI embedder (when an API key is present), embeddings are persisted, a cosmosSearch vector-ivf index is created, and a CLI-style nightly job computes centroids and writes alert documents. The build passed unit tests and ran the seed, index-creation, ingest (embeddings failed in verification due to missing OPENAI_API_KEY but were handled) and a nightly-run simulation against the live cluster. Key issues: the builder implemented aggregation and centroid computations client-side rather than using server-side aggregation; comparisons to anomaly profiles do not use DocumentDB's $search / cosmosSearch vector search; connection/client tuning, retries, and bulk/batched writes are not implemented; dependencies are not pinned to exact versions; no infrastructure-as-code for provisioning the mongoClusters resource is included; README lacks index-tuning guidance; two discovered best-practice items (P12, P18) have no public guidance and should be documented by the product team. Documentation search was available during this run.
