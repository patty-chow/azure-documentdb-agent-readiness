## Notes

I inspected the sample app code (makes a singleton MongoClient, reads DOCUMENTDB_URI from env, creates cosmosSearch vector index with createIndexes, embeds features with OpenAI, stores embeddings in 'employee_vectors', uses replace_one with upsert, computes centroids locally) and then searched Microsoft docs and the installed DocumentDB skills. Most prior beliefs (K01-K11, K13-K17, K19-K20) are confirmed by Microsoft docs or the installed skills; K12 (store embeddings as binary float32) and K18 (persist without embeddings when embedder unavailable) are not documented in Azure DocumentDB public guidance I could find and are therefore marked as prior_knowledge_only. Public docs of particular relevance: the Azure DocumentDB vector-search docs (createIndexes/cosmosSearch, index types and tuning, normalization guidance), the quickstarts (connection string examples and tls), aggregation pipeline docs ($group/$avg), write-performance docs (bulk writes, unordered batches), indexing/TTL and sharding guidance, and the installed skills (documentdb-connection, documentdb-vector-search, documentdb-indexing, documentdb-security, documentdb-sharding, documentdb-monitoring) provided concise, actionable best-practice recommendations useful for this app.
