# 5. Best-practice audit: 16-multi-touch-attribution-model

**Verdict: fail** (8 followed, 3 violated, 4 not applicable)

The sample is a runnable Python (FastAPI) service that seeds synthetic events, computes first-touch/last-touch/linear attribution, stores versioned attribution documents, and exposes a LangChain/OpenAI wrapper. Most gallery hygiene items (README, .env.example, tests, pinned requirements) are present. However a core functional requirement was not met: the reference required that attribution be computed by aggregation pipelines executed in Azure DocumentDB, but the implementation computes attribution client-side in Python. Because the sample therefore does not do what the starter prompt explicitly asked, the verdict is FAIL. The report lists file/line evidence, the cause for each unmet or partly-met requirement, smallest fixes, practice checks, decision reviews and documentation gaps the product team should address.
