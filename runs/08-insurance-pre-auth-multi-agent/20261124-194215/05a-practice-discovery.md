## Where public sources contradict the model

### P22: Do not store very large binary/PDF blobs inline in a hot collection; for Azure DocumentDB public guidance, prefer splitting very large fields into a side collection keyed by _id rather than co-locating large blobs in frequently-scanned collections.

- **The model believed:** Limit document size: do not embed large binary or PDF blobs in documents; instead store large files in blob storage (Azure Blob) and include a reference (URL or id) in the DocumentDB document. (knowledge of `general`)
- **The source says:** Do not store very large binary/PDF blobs inline in a hot collection; for Azure DocumentDB public guidance, prefer splitting very large fields into a side collection keyed by _id rather than co-locating large blobs in frequently-scanned collections.
- **Source:** [documentdb-data-modeling](https://github.com/Azure/documentdb-agent-kit/blob/main/skills/data-modeling/SKILL.md)
