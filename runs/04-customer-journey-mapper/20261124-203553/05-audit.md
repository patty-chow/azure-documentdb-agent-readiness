# 5. Best-practice audit: 04-customer-journey-mapper

**Verdict: pass_with_findings** (7 followed, 6 violated)

The sample implements the requested customer-journey reconstruction and LLM prompt engineering in Node.js. Core features are present: a singleton MongoClient, an idempotent seed script that creates a compound index ({customerId:1, timestamp:1}) and inserts synthetic events, an aggregation helper that returns chronological timelines and channel groupings, and an agent module that formats a structured timeline into a prompt and calls an OpenAI-compatible client to summarize inflection points. Unit tests (prompt-builder) run without a live cluster. The LLM end-to-end step was not exercised because OPENAI_API_KEY was not provided during verification, but the code path is implemented.

Findings that need attention before publishing: the aggregation work is done with a client-side group after a find().sort(...).toArray(), rather than with a server-side aggregation pipeline (no $group/$match pipeline or allowDiskUse), which makes the implementation memory-unsafe for large customers and misses opportunities for index-backed grouping in the DB. The sample does not implement pagination/streaming or request-retry/backoff handling for heavy or transient workloads. .env.example is present but omits a few optional env knobs the code reads (pool-sizing). There is no IaC (ARM/Bicep/Terraform) example using the correct Microsoft.DocumentDB/mongoClusters resource type. Several of these gaps were predicted in the prompt-review readiness flags; the builder addressed many (env variables, seed idempotency via a seed marker) but left others to be added in documentation or a follow-up change (IaC, more robust DB-side aggregation, retry/backoff and pagination).
