# 5. Best-practice audit: 03-substitute-product-finder

**Verdict: pass_with_findings** (8 followed, 3 violated)

The sample implements the requested FastAPI + Beanie app, an ingestion script, vector-storage fields, and a simple retailer-style UI. It reads DOCUMENTDB_URI from a config and fails fast on missing/invalid connection strings. The ingestion script batches inserts and creates a vector-index command (best-effort). Major issues: the server-side aggregation uses a non-DocumentDB knn operator (knnBeta) rather than the DocumentDB 'cosmosSearch' payload (so server-side vector search is likely to fail on DocumentDB), the ingestion script is not idempotent, the index-creation and MCP-based verification could not run in this environment because management/write tools were disabled, and dependency installation failed on this runtime (pydantic-core build). The build decisions are generally supported by the trace; skills for DocumentDB were loaded, but the vector-search skill guidance (use cosmosSearch) was not followed when implementing the server-side pipeline. See Requirement Results, Practices checks and Doc gaps for details and fixes.
