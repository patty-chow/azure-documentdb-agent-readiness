## Notes

I inspected the sample app files (config, main, models, routes, ingest and quick verification scripts) and then searched Microsoft documentation for Azure DocumentDB (the product pages on docs.microsoft.com). The public docs provide detailed guidance for connection strings, authentication (including Microsoft Entra/managed identities), network controls (firewall/Private Link), single-client lifetime usage, vector-index algorithms (DiskANN/HNSW/IVF) and index parameters (m, efConstruction, efSearch, lBuild, lSearch, numLists, dimensions), the requirement that vectors be numeric arrays (number[]), $search usage and $meta searchScore projection, bulk ingestion/batch and SDK bulk features, and monitoring/retry guidance for 429s and RU monitoring. Where a prior belief was a general app practice not found in Azure DocumentDB docs (K18) I marked it prior_knowledge_only. One prior belief (K19 recommending float32-only) is contradicted by public docs which explicitly describe half-precision and product quantization as supported options; I recorded the service guidance as the practice for that belief.
