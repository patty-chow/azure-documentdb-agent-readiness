# 5. Best-practice audit: 09-trade-settlement-tracker

**Verdict: pass_with_findings** (10 followed, 7 violated, 1 not assessable)

The repository contains a complete Node.js + Mongoose settlement-tracker sample implementing the features the starter prompt asked for (state-machine trade documents, transactional state advancement, transition logging, change-stream watcher for FAILED settlements, and an aggregation endpoint for settlement rates). The builder documented run steps and included a .env.example. Runtime verification against the live cluster was attempted but blocked by environment restrictions (npm registry resolution errors and write tools disabled on the MCP server). Key best-practice items are followed (singleton client, pool sizing, transaction usage, indexed aggregation fields, idempotent seed), but there are gaps to fix before publishing: pin dependencies / commit a lockfile, add unit tests that run without a live cluster, avoid unbounded stateHistory growth (or add an append-only audit collection / TTL), persist change-stream resume tokens and implement robust backoff/retry semantics around transient failures, and provide infra-as-code if you intend the gallery sample to include provisioning. The decision log largely matches the recorded events: skills were loaded as claimed and MCP calls and npm failures are visible in the trace. See requirement-by-requirement results, practice checks and recommended fixes below.
