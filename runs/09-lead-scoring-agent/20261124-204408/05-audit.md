# 5. Best-practice audit: 09-lead-scoring-agent

**Verdict: pass_with_findings** (11 followed, 6 violated, 4 not assessable)

The sample is a functioning Node.js lead-scoring demo that connects to an existing Azure DocumentDB cluster, seeds idempotent sample data, fetches lead context (lead, activities, company, engagement signals), reasons (LLM or heuristic) and writes score + rationale back to the lead document. Seed, index creation, and unit tests executed in this run. Key findings: (1) the implementation meets the core starter-prompt requirements except that it does not instantiate a LangChain Agent object (the orchestration is handwritten), (2) there are small but important env-var/name inconsistencies (OPENAI_MODEL vs OPENAI_CHAT_MODEL / DB_NAME vs DATABASE_NAME) that risk confusing users and CI, and (3) the sample intentionally omits vector/embedding usage (documented), so vector-index-related checklist items are not implemented. I verified which DocumentDB best practices are present in code and which are absent; the report includes practice checks, decision reviews, and recommended documentation/tooling gaps the product team should address.
