# 5. Best-practice audit: 01-patient-record-summarizer-rag

**Verdict: pass_with_findings** (16 followed, 3 not assessable, 5 violated)

The sample implements a working Python RAG demo that stores chunked patient records with embeddings, prefilters by patientId, re-ranks candidates in-application using cosine similarity, constructs a structured clinical-summary prompt, and returns grounded answers with document references. Unit tests run locally and mock external services. Major gaps are: no DB-side vector index is created (the builder intentionally used an application-side rerank fallback because authoritative index-creation docs were not available in the run), no provider-side $search/knn usage, limited retry/429 handling, and a few missing documentation/IaC pieces the gallery expects. Note: this run had no external documentation search available, so many of the discovered-practice entries come from files in the repository rather than public docs.
