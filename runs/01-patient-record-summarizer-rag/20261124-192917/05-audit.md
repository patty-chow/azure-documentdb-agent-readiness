# 5. Best-practice audit: 01-patient-record-summarizer-rag

**Verdict: pass_with_findings** (13 followed, 9 not applicable, 3 not assessable, 1 violated)

The sample implements the core retrieval and DocumentDB vector-index flow: it seeds chunked patient documents with embeddings, creates a cosmosSearch vector-HNSW index (1536 dims), runs pre-filtered vector KNN queries, and exposes a /search endpoint that returns the retrieved chunks and similarity scores. Several gallery expectations are missing or incomplete: the LlamaIndex RAG end-to-end flow was not executed or demonstrated, the summarization prompt-engineering step was not implemented (the app concatenates texts instead), error handling for empty queries / embedding failures is absent, dependencies are not pinned to exact versions, and there are no offline unit tests or IaC for provisioning the cluster. The run trace shows an attempted MCP tool index creation failed (management tools disabled), and the builder correctly fell back to the documented createIndexes runCommand. See the requirement-by-requirement results, practice checks, decision reviews and documentation gaps below.
