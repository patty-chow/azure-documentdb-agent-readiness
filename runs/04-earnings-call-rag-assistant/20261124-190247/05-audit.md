# 5. Best-practice audit: 04-earnings-call-rag-assistant

**Verdict: pass_with_findings** (13 followed, 9 violated, 2 not assessable, 4 not applicable)

The repo implements a working, minimal RAG demo that chunks text transcripts, computes embeddings with sentence-transformers, stores embeddings+metadata in a DocumentDB collection, and exposes a CLI query flow that retrieves top-k passages (client-side cosine) and synthesizes answers (OpenAI or deterministic fallback). Key gallery expectations that the builder omitted or only documented are: LlamaIndex integration and PDF parsing, server-side cosmosSearch KNN usage and programmatic vector-index creation (MCP/cluster writes were attempted but blocked in this run), context-window-aware passage assembly, explicit retry/backoff for DB/embedding calls, idempotent upsert bulk-ingest, tests/mocks that run without a live cluster, and infrastructure-as-code for the cluster. No secrets are committed; .env.example and pinned requirements exist. The build was limited by this environment: pip build of heavy wheels failed and MCP management/write tools were disabled, and those failures are cited in the events trace and the builder's decisions.
