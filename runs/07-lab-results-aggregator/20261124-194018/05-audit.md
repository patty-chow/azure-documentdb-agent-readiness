# 5. Best-practice audit: 07-lab-results-aggregator

**Verdict: pass_with_findings** (11 followed, 4 violated)

The sample implements the core prompt: an async Python FastAPI service using Beanie that stores one-document-per-sample lab results, computes moving averages with $setWindowFields, and demonstrates change-stream alerts. Key findings: the app creates and reuses a single async client, seeds idempotently, creates the compound index, and verified the aggregation used the index. Shortcomings: the moving-average aggregation is implemented using the Motor client rather than Beanie's aggregation API (the prompt asked for Beanie-driven pipeline), the requested flagging inside the aggregation pipeline was not added (flagging is done in application logic instead), there are no offline unit tests, and infrastructure-as-code is not provided. Several operational guidance gaps were noted (Beanie/Motor compatibility matrix, tests-without-cloud examples). See requirement-by-requirement results, practice checks, decision reviews and documentation gaps below.
