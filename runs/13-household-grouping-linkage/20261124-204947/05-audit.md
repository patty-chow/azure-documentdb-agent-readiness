# 5. Best-practice audit: 13-household-grouping-linkage

**Verdict: pass_with_findings** (12 followed, 3 violated, 4 not applicable, 1 not assessable)

The sample implements the requested functionality (Mongoose models, household-linking, household documents with member refs, endpoints for household CLV and aggregated product holdings) and was exercised against a live Azure DocumentDB cluster. Key findings: (1) the CLV endpoint computes totals by populating members and summing in application code rather than using an aggregation pipeline as the reference requires; (2) connection options enable retryWrites=true while Azure guidance and some samples prefer retryWrites=false for certain workflows; (3) .env.example exists but does not list every runtime setting the app reads (e.g., PORT, MAX_POOL_SIZE); (4) seed script is idempotent for its own seed-tagged documents but does not create indexes idempotently; (5) no DB-level JSON Schema validators, no IaC for provisioning, and no offline unit tests were provided. I exercised the app (seed, link, verify) against the live cluster and used the MCP tools to inspect indexes and an explain plan. See requirement-by-requirement results, the practice checks, decision reviews and documentation gaps below.
