# 5. Best-practice audit: 01-unified-customer-profile-store

**Verdict: pass_with_findings** (9 followed, 5 violated)

The sample implements the requested Node.js + Mongoose customer-profile upsert service correctly: schema, model, HTTP ingest endpoint, idempotent upserts by stable customerId, $set dotted-path merging, single shared connection, and an idempotent seed script that ensures the unique index. Most of the prompt-level requirements are met. The run environment prevented installing dependencies and running the seed/app here (npm install failed), and an attempt to use the MCP write tools also failed because write tools were disabled — these verification gaps are recorded below. Several gallery-level best-practices (retry/backoff, requestCharge logging, dependency pinning / lockfile, infra-as-code) are missing or only partially implemented and should be fixed before publishing.

Note: documentation search was available during the run and the auditor used the discovered practice results (P01..P22) and Microsoft Learn searches to ground practice availability. The builder loaded several DocumentDB skills (documentdb-driver, documentdb-connection, documentdb-data-modeling, documentdb-indexing, documentdb-local-deployment, documentdb-azure-deployment) during the build; where a skill covered an expectation the builder generally followed it, but a few checklist items remain outside the starter prompt/skills and were not implemented.
