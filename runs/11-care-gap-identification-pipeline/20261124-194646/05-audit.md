# 5. Best-practice audit: 11-care-gap-identification-pipeline

**Verdict: fail** (12 followed, 6 violated, 6 not applicable, 1 not assessable)

The sample implements the core pipeline (aggregation + prioritization + talking points) and is runnable against the provided cluster. It follows many DocumentDB best practices (singleton MongoClient, indexes for patient_id and visits, seed script idempotency, env-driven configuration). However there are several important gaps: (1) the agent will dump patient records (including contact/identifiers) directly into an LLM prompt when OPENAI_API_KEY is present (no PHI redaction or warning) — this is a privacy/security risk for healthcare data; (2) the aggregation computes screening logic client-side rather than inside the aggregation pipeline (the pipeline returns last_visit but the gap detection is done in Python); (3) some DocumentDB skill guidance was loaded but not applied (retryWrites setting missing, no explain()/allowDiskUse usage, missing pre-filter $match before $lookup), and (4) repository hygiene gaps: dependencies are not pinned to exact versions, infra-as-code is missing, and there are no unit tests that run without a live cluster. Because the sample as-written will send identifiable patient data to an external LLM (if the API key is set) with no guidance or redaction, I judge the build 'fail' until the PHI/LLM behavior is fixed or documented with explicit protections.

Note: documentation search tools were reachable during this run; the reviewer loaded many DocumentDB skills and Microsoft docs while auditing, so 'not found' means the guidance is not prominent or was not discovered earlier by the builder's open search, not that docs are unreachable.
