# 5. Best-practice audit: 11-care-gap-identification-pipeline

**Verdict: pass_with_findings** (17 followed)

The sample is runnable, exercised unit tests, seeds a live cluster idempotently, computes last visits via a server aggregation and implements care-gap detection, prioritisation and talking-point generation. Key correctness features are present: environment-driven connection and LLM credentials, an idempotent seed script, a single reused MongoClient, guideline injection, deterministic unit tests for rule logic, and both an LLM and a deterministic fallback path. Shortcomings that matter to the gallery review: (1) the care-gap classification itself runs in-process (Python) rather than fully in the DocumentDB aggregation pipeline requested by the starter prompt; (2) the sample does not construct provider-specific vector indexes or choose vector-dimension/parameter values tied to an embedding model; (3) the sample advertises LangChain in the prompt/readme and the decision log but the code does not implement a LangChain agent/tool wrapper (the LLM call is made directly via an OpenAI client). Documentation search was not available during this run (documentation_search_available=false), so any “not found” guidance reported below means “not discoverable from this machine” rather than authoritative absence on the web.
