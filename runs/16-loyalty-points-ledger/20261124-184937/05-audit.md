# 5. Best-practice audit: 16-loyalty-points-ledger

**Verdict: pass_with_findings** (9 followed, 3 violated, 3 not assessable)

The sample implements the requested Node.js + Mongoose loyalty ledger: immutable event documents, per-account balances, and multi-document transactions that atomically insert events and update balances. The /balance and /history endpoints and the lifetime-points aggregation with tier derivation are implemented and were exercised against the provided live cluster by the builder. Findings: the seed script is only partially idempotent (it will append duplicate events on repeated runs), transactional retry semantics are not implemented (no retry loop for transient transaction errors / no use of the driver's withTransaction helper), and there are no unit tests that run without a live cluster. Infrastructure-as-code for the cluster is not provided (the run-policy and prompt led the builder to use an existing cluster). Several service-level best-practices are discoverable in the installed DocumentDB skills and were followed (singleton client, TLS via connection string, indexes, unique balance index). Documentation gaps that would help agents/builders include a concise Node.js Mongoose + Microsoft Entra ID (MONGODB-OIDC) example, clarification of write-concern semantics for ledger use, and explicit CLI/Bicep naming guidance for vCore mongoClusters vs older Cosmos DB account resources. The run was able to call the MCP tools and Microsoft Learn search, so 'not found' in this report means actively not present in public guidance the agent saw.
