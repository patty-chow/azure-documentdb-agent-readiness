# 5. Best-practice audit: 02-clinical-trial-matching-orchestration

**Verdict: pass_with_findings** (7 followed, 9 violated, 5 not assessable, 1 not applicable)

The sample is functional and demonstrates the end-to-end patient→match flow using a deterministic eligibility engine, optional LangChain/OpenAI for rationale/consent, scalar prefilters, and client-side vector ranking over stored embeddings. Unit tests pass and the seed script upserts sample trials. Major findings: the sample did not create a service-side cosmosSearch vector index (the MCP create-index attempt failed in this environment), the orchestration/eligibility steps are not implemented as LangChain chains/agents (eligibility is rules-based in-app), dependencies are unpinned, some recommended operational best practices (retry/connection options, JSON schema validation, observability, and production secret storage) are absent, and infrastructure-as-code for a DocumentDB cluster is not included. Many of these omissions stem from choices the builder made (or a refused management-tool operation) rather than code bugs; fixes are small and listed below.
