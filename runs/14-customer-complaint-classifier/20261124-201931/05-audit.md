# 5. Best-practice audit: 14-customer-complaint-classifier

**Verdict: pass_with_findings** (18 followed, 5 violated, 2 not assessable, 4 not applicable)

The repository implements the complaint-classifier pipeline, with Beanie document models, embedding storage, a seed script (idempotent upserts), an index-creation helper, search and hotspots endpoints, and unit tests that run offline. Key runnable pieces are present and tests passed locally. Main findings: (1) the code does not use LangChain for classification even though the prompt required a LangChain agent (the code calls the OpenAI API directly), (2) the pipeline uses raw pymongo find cursor rather than Beanie query APIs when selecting unclassified documents, (3) /search lacks explicit validation / error handling for empty queries and for embedding failures in the app code path, (4) .env.example omits some settings the code expects, and (5) the repository contains index-creation and seed scripts but no infrastructure-as-code for provisioning an Azure DocumentDB cluster. The MCP server was attempted for live verification but write tools were disabled in this run; that prevented live creation of indexes/data (events show documentdb_create_index and documentdb_insert_documents tool calls failed). See requirement_results and checks below for line-level evidence and the smallest fixes to get each requirement met next time.
