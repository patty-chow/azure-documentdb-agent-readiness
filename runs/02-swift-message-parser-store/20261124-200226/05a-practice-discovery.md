## Where public sources contradict the model

### P16: Azure's MongoDB-compatible service ignores client-specified MongoDB writeConcern (w/wtimeout); rely on account consistency settings and the platform's replication semantics rather than setting client writeConcern to tune durability.

- **The model believed:** Use ordered=False and writeConcern w/ appropriate w and wtimeout only if you understand tradeoffs; for maximum throughput prefer lower synchronous write guarantees but ensure app-level validation/compensation for data loss. (knowledge of `mongodb`)
- **The source says:** Azure's MongoDB-compatible service ignores client-specified MongoDB writeConcern (w/wtimeout); rely on account consistency settings and the platform's replication semantics rather than setting client writeConcern to tune durability.
- **Source:** [Supported features and syntax in Azure Cosmos DB for MongoDB 4.0 server version](https://learn.microsoft.com/azure/cosmos-db/mongodb/feature-support-40#user-and-role-management)
