# 5. Best-practice audit: 14-telehealth-session-summarizer

**Verdict: pass_with_findings** (12 followed, 3 violated, 2 not applicable, 1 not assessable)

The sample is a small, readable Python app that implements the core: it accepts a transcript and patientId, uses a context-engineered prompt to get a structured (chief_complaint, assessment, plan, follow_up) summary from an LLM or a deterministic fallback, and stores the structured document into an Azure DocumentDB collection using PyMongo. Key functional and safety items are implemented (singleton client, env-driven secrets, idempotent seeding, patientId index, README). Missing or partial items are mostly documentation, optional vector-index creation, test isolation, and a few production hardening items (retries, diagnostics). The build choices that deviated from the starter prompt (not using LlamaIndex APIs; not creating vector indexes by default) are recorded in decisions.jsonl and justified there; they are defensible but should be called out for the gallery owner. See requirement-by-requirement results, reconciled best-practice checks, decision reviews, and prioritized documentation gaps below.
