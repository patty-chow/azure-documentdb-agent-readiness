# 5. Best-practice audit: 11-correspondent-banking-risk-screener

**Verdict: pass_with_findings** (7 followed, 3 not assessable, 2 violated)

The sample implements the requested correspondent-banking risk-screener: a Python FastAPI endpoint and a LangChain-style agent that embeds correspondent profiles, stores embeddings in Azure DocumentDB, runs server-side vector $search (with deterministic fallbacks), computes a risk score and returns matched entries plus an LLM narrative when an API key is present. Key best-practices from the installed DocumentDB skills were followed (singleton MongoClient, env-driven secrets, idempotent seed). Shortcomings: vector/index creation had API/shape errors and some queries fell back to metadata searches because the live cluster either rejected the createSearchIndexes command or the index shape was not accepted; the sample does not project/return search similarity scores; dependency versions are not tightly pinned; no unit tests are present; and some index-tuning and infra-as-code guidance expected in a gallery sample is missing. See requirement-by-requirement results, practice checks, decision reviews and recommended documentation fixes below.
