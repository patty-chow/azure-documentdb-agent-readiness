## Notes

I inspected the app's code and loaded domain skills relevant to connection, indexing, data modeling, vector search, provisioning, security, local deployment and monitoring. The installed skills (documentdb-*) provided the public guidance recorded above. Two prior-beliefs were contradicted by Azure-specific guidance in the deployment skill: the service indicates retryable writes should be set to false in the connection string (contradicting a general-driver belief to enable retryWrites), and capacity guidance centers on compute tiers (M10/M30...) rather than RU/sec autoscale in the public deployment docs. Several LLM-specific practices (batching, audit logging, PII redaction, strict prompt-output validation) had no explicit Azure DocumentDB documentation in the skills I loaded; I listed those prior beliefs as 'prior_knowledge_only' and recorded the searches attempted. Relevant app touchpoints: connection management, index design (date+category), server-side aggregation, idempotent writes and seed scripts, TLS and secret handling.
