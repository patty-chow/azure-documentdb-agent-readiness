# 5. Best-practice audit: 07-customer-review-sentiment-pipeline

**Verdict: pass_with_findings** (5 violated, 11 followed, 4 not applicable, 4 not assessable)

The sample implements the async Beanie enrichment pipeline, mock + real-OpenAI integration, idempotent seeding, and the requested aggregation. Most developer-facing items (README, pinned dependencies, .env.example, seed script, Beanie models and indexes declaration) are present and runnable. Major findings: the code does not implement a single process-global Mongo client (it creates a new AsyncIOMotorClient on each init), several index/query mismatches (aggregation groups on sentiment_label but the compound index uses sentiment_score), there is no application-level retry/backoff for transient DB or OpenAI failures, and a few helper scripts reference a missing get_motor_client or otherwise duplicate functionality (two run_pipeline implementations). These are correctness / reliability issues to fix before publishing. Many of the product team's best practices are discoverable via the installed DocumentDB skills; a small set are only in the model's prior-knowledge and should be documented. See requirement_results, checks, decision_reviews and doc_gaps for details and minimal fixes.
