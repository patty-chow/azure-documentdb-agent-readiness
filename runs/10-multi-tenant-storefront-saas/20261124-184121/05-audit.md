# 5. Best-practice audit: 10-multi-tenant-storefront-saas

**Verdict: pass_with_findings** (9 followed, 2 violated)

The sample implements the core starter-prompt goals: a Node.js + Mongoose multi-tenant storefront with shared collections, tenantId on every schema, tenant-scoped compound indexes, a repository layer and a defensive tenant-safety plugin. The build ran seed, verify-indexes and the isolation test against the live cluster and validated the compound indexes via the MCP tool. Findings: (1) the seed is not fully idempotent (orders are created unconditionally), (2) the seed and test sometimes bypass the repository layer, (3) no explicit retry/backoff logic was added for transient/429 throttles although connection guidance was consulted, and (4) a handful of gallery expectations (IaC, unit tests without a live cluster, and a more complete .env.example) remain incomplete. Several expected DocumentDB practices are discoverable and were followed (connection reuse, tenant-leading indexes, reading connection string from env, not committing secrets). Two multi-tenant practices (centralized repository-plugin enforcement and automated tests that assert blocking of dangerous repo ops) are prior_knowledge-only in the public guidance and are therefore things the product docs/agent kit should publish to avoid agents inventing them.
