# 5. Best-practice audit: 15-supplier-po-management

**Verdict: pass_with_findings** (8 followed, 6 violated, 1 not assessable)

The sample implements a FastAPI + Beanie service with Supplier and PurchaseOrder models, CRUD endpoints (create/read/delete) and an aggregation endpoint. The repository includes a seed script, README and .env.example. Key shortcomings: update endpoints are missing for both resources; the aggregation runs directly against the Motor collection rather than via Beanie as requested; connection-timeout/retry options are not set; dependencies are not pinned and caused a Beanie init runtime error during verification; list endpoints are unbounded (no pagination); the seed script and index provisioning were not successfully verified because Beanie initialization failed at run time. None of the problems observed are obviously a security failure, but several reduce robustness and prevent verification against the live cluster. See requirement-by-requirement results, practice checks, decision reviews and documentation gaps below.
