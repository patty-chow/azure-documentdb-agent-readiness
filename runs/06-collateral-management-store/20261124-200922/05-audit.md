# 5. Best-practice audit: 06-collateral-management-store

**Verdict: pass_with_findings** (11 followed, 11 violated, 2 not applicable)

The sample implements the core requested functionality: Mongoose schemas, versioned documents with version/createdAt, an LLM classification step, and a server-side aggregation endpoint that computes the collateral coverage ratio using the latest version per asset. The builder ran unit tests (offline via mocks), seeded the live cluster for verification, and used MCP explain tools to inspect the aggregation plan. Missing items are primarily optional-production practices and documentation/operational work the starter prompt did not request (vector-index creation, production retry handling, infrastructure-as-code, and a few documentation points). None of the missing items appears to make the sample insecure or incorrect for its stated demo purpose, but several are important for production hardening and agent discoverability.

Notable verification evidence (examples):
- Model/schemas: app/src/models/collateral.js (version, createdAt, llmTags) and app/src/models/CollateralAsset.js (compound index) show schema and indexes.

- LLM classification used in write path: app/src/llm/classifier.js and invoked in app/src/routes/assets.js line 28–31.

The run evidence shows these choices were deliberate and executed; I flag them below as findings with the smallest fixes to make the sample gallery-ready and agent-findable.
