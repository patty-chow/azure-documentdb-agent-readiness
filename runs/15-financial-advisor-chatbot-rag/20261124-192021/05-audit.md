# 5. Best-practice audit: 15-financial-advisor-chatbot-rag

**Verdict: pass_with_findings** (5 followed, 2 not assessable, 4 violated)

The sample implements a runnable Node.js RAG demo that seeds knowledge documents (with deterministic embeddings), implements a singleton MongoClient, a small in-process retriever + agent memory, and a mocked portfolio tool. Key functionality from the starter prompt is present (local RAG behavior, seeded documents with embeddings, in-memory conversation memory, portfolio tool usage, and citation of retrieved docs and portfolio numbers). The biggest gaps are operational: the DocumentDB native vector index was not created during the build (MCP management tools were disabled in this run), so the sample falls back to in-process k-NN ranking; index creation failed due to management-tool opt-in being disabled. Other findings: some gallery requirements are only partly met (index creation, DB-side $search retrieval, explicit TLS/Entra-ID guidance, tests that run without a live cluster, pinned dependency policy, and cleanup doc). I list line-level evidence for every reference requirement, review every recorded decision, check public practices against the code, and enumerate documentation gaps the product team should address so agents can find authoritative guidance next time.
