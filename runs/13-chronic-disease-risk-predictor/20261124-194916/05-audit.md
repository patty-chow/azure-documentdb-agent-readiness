# 5. Best-practice audit: 13-chronic-disease-risk-predictor

**Verdict: pass_with_findings** (11 followed)

The sample is a runnable Python FastAPI demo that implements the embed → retrieve → reason → generate flow, seeds synthetic high-risk patient profiles (idempotent upserts), and includes a server-side $search/cosmosSearch retrieval with a client-side cosine fallback. Unit tests exercising the offline paths run with mongomock and passed in this run. Key production items are implemented (singleton MongoClient, env-driven secrets, pinned deps, embedding normalization and dims). The main blocking issue encountered during verification was vector-index creation: attempts to create a cosmosSearch vector index via the MCP helper were refused (management tools disabled) and direct createIndexes/db.command calls then failed because the target collection already contained documents with incompatible embedding shapes (server error: expected 1536 dimensions, not 3). The app handles that safely by falling back to a client-side retrieval path, but the server-side vector index was not created in this run. Several documentation and integration gaps remain (index-tuning guidance in the README, a small LlamaIndex->DocumentDB retriever example, seed-index ordering to avoid dimension-mismatch failures, and authoritative guidance on writeConcern/readPreference for DocumentDB). See requirement-by-requirement results, practice checks, decision reviews and recommended doc/tool fixes below.
