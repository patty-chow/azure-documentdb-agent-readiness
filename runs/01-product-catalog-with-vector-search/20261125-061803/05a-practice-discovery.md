### P05: Store embeddings as BSON Binary float32 bytes without additional embedded metadata (dims/dtype) and infer dimension from byte length when reading, rather than including explicit dimension/dtype metadata in the document.

- **The model believed:** When storing embeddings as BSON Binary, choose a single Binary subtype and explicit endianness and include metadata (e.g., dtype='float32', dims=1536) in the document so clients/indexes decode vectors correctly. (knowledge of `mongodb`)
- **The source says:** Store embeddings as BSON Binary float32 bytes without additional embedded metadata (dims/dtype) and infer dimension from byte length when reading, rather than including explicit dimension/dtype metadata in the document.
