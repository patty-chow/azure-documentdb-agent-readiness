# 5. Best-practice audit: 01-product-catalog-with-vector-search

**Verdict: pass_with_findings** (25 followed)

No external documentation search server was reachable from this run; all discovery was limited to files in the workspace. The sample implements a Flask web app (app.py) that reads DOCUMENTDB_URI and OPENAI_API_KEY from the environment, seeds a sample_retail_01.products collection with product documents and BSON Binary float32 embeddings, attempts a plausible MongoDB-7-style IVF/knn createIndexes call (which the target cluster rejected), and exposes POST /search which embeds the incoming query (when OPENAI_API_KEY is set) and otherwise performs client-side ranking by unpacking BSON Binary embeddings and computing cosine similarity. The repository provides a .env.example, pinned requirements.txt, a seed.py script that is idempotent (drops the collection first), a verify_search.py script for local verification using bundled embeddings, and a clear README. Main issues to fix before publishing: (1) the seed/embeddings in the repo are 32-dimensional while text-embedding-ada-002 produces 1536-dim vectors — the seed/index logic and README should explicitly validate and document dimensions; (2) the server-side index createIndexes syntax is vendor-specific and the seed currently uses a plausible but unverified 'knnVector' command which failed on the test cluster — provide a tested index snippet for the supported clusters or store an indexable numeric-array field as an alternative; (3) there are no unit tests that run without a live cluster; (4) no infrastructure-as-code for provisioning the cluster is included (the run environment provided the cluster). Decisions recorded in decisions.jsonl largely match what appears in the repository; two decisions based on model defaults (which env var to use for embeddings, and which createIndexes syntax to try) are defensible but flagged as 'questionable' because no authoritative external doc was available in this run. See Requirement Results, Practice Checks, Decision Reviews and Doc Gaps below for details and line-level evidence.
