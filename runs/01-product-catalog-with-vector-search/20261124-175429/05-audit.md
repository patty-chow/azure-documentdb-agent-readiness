# 5. Best-practice audit: 01-product-catalog-with-vector-search

**Verdict: pass_with_findings** (15 followed, 6 violated, 4 not applicable, 1 not assessable)

The sample is a runnable Python/Flask demo that implements embedding, storage, an index-creation payload, and a /search endpoint with an in-app fallback. Major strengths: singleton MongoClient, embedding normalization, embedding metadata, use of $search/cosmosSearch in the aggregation pipeline, not returning raw embeddings in responses, and clear local-gateway quickstart. Key findings that the owner should fix before publishing: (1) the sample stores embeddings as BSON Binary bytes (packed float32) even though Azure DocumentDB's public guidance requires number[] vectors to be indexed — this prevents the server-side vector index from working as the README intends; (2) the vector-ivf hyperparameter (nlist=100) is not tuned for tiny demo datasets; (3) the code does not verify index creation/availability before serving search traffic; (4) no retries/exponential backoff are implemented for DB or embedding API calls; (5) dependencies are not pinned to exact versions; (6) the sample does not document or demonstrate Microsoft Entra ID authentication (it uses connection-string auth by default) though the service supports Entra ID. I inspected the repository files, the builder's decisions and the event trace (skills loaded and pip-install failure). The environment prevented running dependencies or verifying end-to-end against a live cluster; where verification required a running DocumentDB gateway or pip installs I mark the checks accordingly and give minimal fixes the owner can apply.
