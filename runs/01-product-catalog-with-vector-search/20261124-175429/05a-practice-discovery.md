### P02: When using IVF, choose numLists relative to dataset size (use documentCount/1000 for up to ~1M documents, and consider other index types like DiskANN beyond that); tune nProbes (nProbes/nProbes) to trade recall for latency rather than using a single universal sqrt(N) rule.

- **The model believed:** Tune IVF parameters relative to dataset size: pick nlist (number of inverted lists) proportional to sqrt(N) and set search params (nprobe) to trade recall vs latency; document chosen defaults and allow configuration. (knowledge of `general`)
- **The source says:** When using IVF, choose numLists relative to dataset size (use documentCount/1000 for up to ~1M documents, and consider other index types like DiskANN beyond that); tune nProbes (nProbes/nProbes) to trade recall for latency rather than using a single universal sqrt(N) rule.
- **Source:** [Integrated vector store in Azure DocumentDB](https://learn.microsoft.com/azure/documentdb/vector-search#example-using-an-ivf-index)

### P04: Store vectors as numeric arrays (number[]) so they can be indexed; embedding values stored as other types (for example raw BSON Binary) are not accepted by the vector index and will not be indexed.

- **The model believed:** When storing embeddings in BSON, use a deterministic binary representation (e.g., serialize float32 little-endian into BSON Binary subtype) and document the serialization format so clients and index creation use the same layout. (knowledge of `mongodb`)
- **The source says:** Store vectors as numeric arrays (number[]) so they can be indexed; embedding values stored as other types (for example raw BSON Binary) are not accepted by the vector index and will not be indexed.
- **Source:** [Integrated vector store in Azure DocumentDB](https://learn.microsoft.com/azure/documentdb/vector-search#example-using-an-ivf-index)
