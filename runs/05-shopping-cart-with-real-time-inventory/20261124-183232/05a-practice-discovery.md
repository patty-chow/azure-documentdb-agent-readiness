## Notes

I inspected the sample app files and used Microsoft Learn documentation plus installed DocumentDB skills to discover public best-practice guidance relevant to the app. Many prior beliefs derived from MongoDB / CosmosDB general knowledge are confirmed by Azure DocumentDB docs (connection handling, TLS, single-client reuse, pool/timeouts, transaction lifetime and short transactions, retry/backoff, sharding guidance, indexing, vector index algorithms, monitoring via Azure Monitor, and using explain()). The major contradiction: Azure DocumentDB does not use RU/s pricing — it bills by compute tier and storage rather than request units; guidance that mentions RU/s applies to Cosmos DB (RU-based) not to Azure DocumentDB. Several prior beliefs about Mongoose optimisticConcurrency, explicit readConcern/writeConcern usage, and explicit projection-to-reduce-RU wording had no authoritative DocumentDB page that directly matched them; those remain as prior_knowledge_only and I recorded the searches I ran.

Prior beliefs the discovery step did not classify: K05, K09, K11, K14, K16, K17. See 05a-prior-beliefs.json.
