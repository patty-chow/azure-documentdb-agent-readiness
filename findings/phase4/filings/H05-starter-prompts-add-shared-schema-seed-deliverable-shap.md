# Starter prompts: add shared schema/seed, deliverable-shape and gallery-contract blocks, and pin down underspecified prompts

> This repository belongs to a colleague (abinav2307); this filing should be coordinated with them before it is opened.

## What happens today

Each starter prompt (`samples/<vertical>/NN-<slug>.md`, generated by `loop/import_samples.py` from the Samples spreadsheet) is one short paragraph naming a language, framework and DocumentDB feature. It omits:

- **The data contract.** Across all 100 prompts, "seed", "fixture", "synthetic", "acceptance" and "definition of done" appear 0 times; "collection" 6, "upsert" 3. Yet `loop/run-environment.md` tells the agent to "load the sample data", and the shared requirements section requires an idempotent seed script.
- **The deliverable shape.** CLI vs HTTP API, response JSON, scheduler, real provider vs stub, agent output schemas.
- **The non-functional list the audit scores.** `requirements/<slug>.md` ("What a gallery sample also needs": env-var secrets, `.env.example`, pinned dependencies, offline unit tests, IaC, README clean-up) plus discovered checks (PII minimisation before LLM calls/logs, monitoring, input validation, provenance, token budgets). `factory/agents/builder.py` `build_app` never sends these to the builder; the auditor records 488 misses as `cause: prompt_silent`.
- **That the named framework is mandatory.** 46 prompts name LangChain and 16 LlamaIndex; in the latest build of each, about 21/46 and 13/16 have no import. `requirements/` already checks this; the builder never sees it.

Also, `gallery_section()` in `loop/draft_requirements.py` copies one static vector-search block into every `requirements/*.md` (101 of 102 files carry the `/search` lines), so non-vector samples are graded on `/search` errors and similarity scores. Its source, `requirements/retail-semantic-search.md` line 15 ("Embeddings are stored as BSON binary vectors."), is unmeetable: `cosmosSearch` indexes (vector-ivf, vector-hnsw, vector-diskann) index `number[]` arrays.

## Why it matters

152 findings across **81 of the 100 samples** (one experiment run, gpt-5-mini with Agent Kit and MCP; the four themes behind this issue cover 15, 63, 21 and 24 samples, which overlap to 81 distinct samples). These counts come from a single run and are expected to move after the harness fixes land; re-baseline before quoting them outside the team. Agents searched Learn and the kit for schemas that cannot exist, invented field names that differ between reruns of the same prompt, shipped LangChain/LlamaIndex samples without the library, sent unredacted seeded patient and account data to the LLM, and invented TTLs, retention periods and formulas. Mis-filed as Learn gaps, these dilute the DocumentDB signal the experiment measures.

## Proposed change

1. **One shared file, `prompts/gallery_contract.md`**, appended to every starter prompt by `build_app` (in the `task` f-string, after `ctx.sample_block()` and before `<skills_the_review_found_relevant>`, under a `<gallery_contract>` tag) and used by `gallery_section()` as the source of the shared requirements instead of slicing `requirements/retail-semantic-search.md` from its "## What a gallery sample also needs" marker, so builder and auditor read one list. Per-sample prompts then state only what differs (for example "CLI REPL instead of HTTP"). Two parts:
   - *Deliverable shape (unless the prompt says otherwise):*
     - a small HTTP API (FastAPI for Python, Express for Node.js) plus one script or CLI command that exercises it end to end; agents and pipelines are invoked through it;
     - scheduled work in-process (APScheduler / node-cron), times in UTC, cron string in the README with a note on moving it to an Azure Functions timer trigger;
     - external providers (email, SMS, push, brokerage, payments, OCR) behind a stub interface, real-provider settings listed in `.env.example`, never called by tests;
     - multi-agent flows run sequentially, each agent returning JSON that matches a schema documented in the README (fields, types, example);
     - GET with query parameters for reads, JSON body for writes; `lat`/`lon` in the API (GeoJSON stores [lon, lat]); errors as `{"error": string, "detail": string}` with a 4xx/5xx status;
     - vector hits carry the similarity score, projected after the `$search`/`cosmosSearch` stage with `{"$meta": "searchScore"}`; grounded answers return a `sources` array of `{id, chunk_id, snippet}`;
     - the README ends with an "Acceptance checklist" of 3-6 verifiable statements.
   - *Every gallery sample also ships:*
     - secrets and connection settings only from environment variables; `.env.example` lists every variable the code reads, with placeholders and the same names as the code;
     - dependencies pinned to the exact tested versions (`==` / exact in package.json), with the tested driver version named in the README;
     - unit tests that run with no cluster (mock or in-memory driver) and a separate integration suite that runs only when the connection setting is present; the README says how to run each;
     - README sections What this shows / Prerequisites / Setup / Run / Tests / Monitoring (cluster metrics and slow-query logs to watch, one `az monitor` command) / Clean-up (drop the sample database; `az documentdb mongocluster delete` if a cluster was created);
     - data minimised and identifiers masked (last 4 characters) before any model call, log or trace, with the rule stated in a README "Data handling" note; mandatory for customer, patient or financial records;
     - request bodies and query parameters validated (shape, length, type) before they reach a query;
     - aggregations and collection scans run as background jobs with a status endpoint, not inside a request handler;
     - context sent to a chat model fits a stated token budget with an answer buffer, heuristic in the README;
     - provenance (model, prompt template id, embedding model, timestamp) on model-produced documents;
     - every fallback or demo mode (pseudo-embeddings, sandbox send, seed sizes) logged with `log_decision`;
     - IaC using the `Microsoft.DocumentDB/mongoClusters` resource type;
     - the name "Azure DocumentDB" throughout, with no former or neighbouring product name.
2. **`main.py run --no-contract`** (new `RunContext.no_contract` field, which does not exist today, passed through `loop/run_loop.py`) so the prompt-only baseline stays reproducible.
3. **Split `gallery_section()`** into common and vector-search parts (index dimensions, index parameters, `/search` errors, similarity score); include the vector bullets only when the sample's concepts or prompt name vector search, use the prompt's own route name (e.g. `/formulary-search`) instead of a generic `/search`, and add bullets derived from the deliverable shape (surface, acceptance checklist). Regenerate `requirements/*.md` (this also removes the spurious `/search` lines from `requirements/07-mortgage-application-multi-agent.md`); fix `requirements/retail-semantic-search.md` line 15 to require `number[]` embeddings.
4. **Per-sample "Schema and seed data" block** as an extra Starter Prompt row in the spreadsheet (the importer already appends extra rows as prompt paragraphs, so no code change), 120-200 words:
   - database and collections with key fields and types;
   - 3-5 example documents inline, or a linked fixture (`samples/<vertical>/fixtures/<NN>-*.json`) when larger than 5 documents;
   - seed size (50-500 unless the sample needs more), synthetic, CC0; for clinical/financial samples no real PHI/PII, sanctions or customer data;
   - upsert key so the seed can run twice with no duplicates;
   - the domain reference the README must reproduce (formula, tag mapping, taxonomy, bucket boundaries, JSON schema);
   - 3-6 checkable "definition of done" assertions.

   All 100 rows get the block; the 63 flagged samples first. Worked examples: banking-02 SWIFT (`swift_messages` with `:20:`/`:23B:`/`:32A:`/`:50K:`/`:59:` mapped to fields, required tags per message type, 200 synthetic messages, upsert on `message_id`, done = re-posting the 5 samples stores 0 new and a message missing `:32A:` gets a 400) and customer-360-15 cohorts (`customers`, `events`, `cohort_snapshots`; 1,000 synthetic customers over 12 months; a stated 30-day retention rule; done = 12 cohort rows, a `$bucket` and a `$facet` stage, refresh replaces snapshots). Answering this once in the sheet also removes the seed-script question the prompt-review stage asks on every run.
5. **One- or two-sentence pins for 15 prompts**, with a matching bullet under "What the starter prompt asks for" in `requirements/<slug>.md` where it is missing (the framework bullets already exist):
   - *Framework is mandatory; do not call the OpenAI SDK directly:*
     - fintech 01 fraud-detection: expose `vector_search` as a LangChain `Tool` invoked from a LangChain agent; the `langchain` import must be in the agent entry point; link the Learn "LangChain Azure DocumentDB integration" section.
     - banking 07 mortgage: each agent is a LangChain.js agent or Runnable composed by a LangChain orchestrator; `langchain` / `@langchain/*` are dependencies and imported; the `mongodb` driver for DocumentDB access. Do not link the Learn LangChain page here, since its vector-store integration is Python-only.
     - customer-360 08 segmentation: register the aggregation as a LangChain `Tool` named `documentdb_aggregate` and pass it to the agent.
     - customer-360 14 complaint classifier: classification runs through a LangChain `PromptTemplate` and chat model in the code path the app executes.
     - healthcare 10 drug formulary: seeding and query embeddings go through LlamaIndex (`Settings.embed_model`); link the Learn "LlamaIndex Azure DocumentDB integration" section.
   - *Fix the parameter left open:*
     - fintech 01 AML: about 60 fixture transactions over 8 accounts with exactly one structuring chain, one rapid pass-through chain and one 3-hop cycle; a test asserts those three and nothing else.
     - healthcare 02 trial matching: fixed trial schema (`trialId`, `title`, `criteria.inclusion[]`/`exclusion[]` of `{field, op, value}`, `embedding: number[]`) enforced by a `$jsonSchema` validator.
     - retail 09 inventory reorder: `sales_velocity`, `lead_times`, `purchase_orders` shapes; seed of 30 SKUs, 3 suppliers, 14 days, with `--scale small|medium|large`.
     - fintech 11 market-news: webhook POST to `WEBHOOK_URL` with `{alertId, ticker, headline, sentiment, articleId, firedAt}` and a bearer token from `WEBHOOK_TOKEN`; a local receiver lets a test assert one delivery.
     - customer-360 11 consent store: `CONSENT_RETENTION_DAYS` default 365, documented as a demo default, not legal guidance.
     - healthcare 19 care coordination: `provenance {model, promptTemplateId, embeddingModel, generatedAt, sourceDocIds[]}` on every care plan.
     - retail 19 cross-sell: embed the basket at request time, query with `$search`/`cosmosSearch`, rank by `0.6 * similarityScore + 0.4 * log1p(coPurchaseCount) / log1p(maxCoPurchaseCount)` and return the components.
     - fintech 19 option chain: keyset pagination on `strike` (`?after=<strike>&limit=200`) returning `nextToken`.
     - customer-360 19 proactive outreach: SMTP and Twilio providers behind `SEND_MODE=sandbox|live`, sandbox default, live settings in `.env.example`.
     - banking 20 open-banking cache: demo `CACHE_TTL_SECONDS=5`, `STALE_WINDOW_SECONDS=10`, with a README note on production values.
6. **Follow-up, not in this change:** paste the shared blocks into the spreadsheet's Starter Prompt column so published prompts carry them too.

Not proposed: any Learn page for these items (they are application design, and the Learn LangChain/LlamaIndex pages already exist). Out of scope and filed separately as Agent Kit items: projection on `find`, bulk upserts in seeds, `schemaVersion` fields, Mongoose `autoIndex:false`, atomic claim with `findOneAndUpdate`, Entra ID over SCRAM, `AsyncMongoClient` over Motor.
