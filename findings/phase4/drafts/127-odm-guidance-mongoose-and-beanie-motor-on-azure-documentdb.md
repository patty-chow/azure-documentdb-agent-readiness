# Beanie quickstart and Mongoose tutorial: version, startup and production-indexing guidance

**Pages:**
- https://learn.microsoft.com/en-us/azure/documentdb/quickstart-python-beanie
- https://learn.microsoft.com/en-us/azure/documentdb/tutorial-nodejs-mongoose

## What happened in the runs
We ran an agent-readiness experiment: 100 Azure DocumentDB sample apps generated by an agent (gpt-5-mini, with the DocumentDB Agent Kit and the Learn MCP server). In 8 samples the agent did not cite DocumentDB-specific ODM guidance and wrote ODM code from memory:

- **Beanie (4 Python ODM samples):** the generated apps pinned **Beanie 1.x with Motor**. The pins found in the run folders were `beanie==1.16.4` with `motor==3.5.3`, plus `beanie==1.21.0` and `beanie==1.25.0` with `motor==3.1.1`. The agent also did not confirm whether `init_beanie` builds declared indexes on DocumentDB.
- **Mongoose (4 Node.js samples):** the agent did not cite guidance on `autoIndex: false` in production, building indexes in a deploy step, `.lean()` on read paths, or `strict` schemas.

The audit graded these practices as `prior_knowledge_only` or `not_assessable`.

## Correction: the pages already cover this
The original draft said the Learn pages lacked this guidance. That is wrong for the current pages (both updated 2026-11-24):

- **quickstart-python-beanie** uses Beanie 2.2.0 with PyMongo 4.19.0 and `AsyncMongoClient`, and says it does "not" use Motor. Its "Already using Beanie?" section tells Beanie 1 + Motor apps to update to Beanie 2 and `AsyncMongoClient`. It says to reuse `AsyncMongoClient` and `init_beanie()` at application startup with one client per process. It also says Beanie creates the declared index during initialization.
- **tutorial-nodejs-mongoose** connects with `autoIndex: false`, calls `Product.createIndexes()` explicitly, and says that in production index creation should be a separate deployment step. It uses `.lean()` on the list endpoint and `strict: 'throw'` on the schema. It notes that Mongoose validation runs in the application, not in the database.
- The Agent Kit `connection` skill also says to use PyMongo's `AsyncMongoClient`, not Motor, and records Motor's deprecation.

## Residual (not enough for a separate issue)
Two small gaps remain:
- The Beanie quickstart has no embedding/vector example. It doesn't show an embedding typed as `List[float]` or point to the cosmosSearch vector index (BSON binary vectors are not indexed).
- The Mongoose tutorial uses `.lean()` without a projection.

Both are minor. The vector-search pages are the right home for the vector-typing point. Since the core ask is already met, this finding is dropped. The gap the runs show is retrieval: the agent didn't find or cite pages that exist. That belongs with the pipeline/agent-kit retrieval themes, not with a Learn content change.

## Verification

### 1. Already covered? - already_covered
Both named pages already contain what the draft asks for.
- https://learn.microsoft.com/en-us/azure/documentdb/quickstart-python-beanie: "This example uses Beanie 2 and PyMongo's asynchronous client, not Motor." It also has an "Already using Beanie?" section on moving Beanie 1 with Motor to Beanie 2. It says "Reuse `AsyncMongoClient` and `init_beanie()` at application startup. Keep one client per process." and "Beanie creates the declared unique index during initialization."
- https://learn.microsoft.com/en-us/azure/documentdb/tutorial-nodejs-mongoose: the connect options include `autoIndex: false`. The page says "In production, manage index creation as a separate deployment step". The list query uses `.lean()` and the schema uses `strict: 'throw'`.
- /private/tmp/claude-501/-Users-julietai-claude/40f65f7c-640c-44c6-8eab-a8434709e1ff/scratchpad/phase4/documentdb-agent-kit/skills/connection/SKILL.md, lines 45-49: use `AsyncMongoClient`, "not Motor", with Motor's deprecation noted.
- Not covered: `List[float]` embedding typing in the Beanie page and projection together with `.lean()`. Both are minor.

Caveat: both pages show updated_at 2026-11-24T17:09Z, close to the run timestamps (2026-11-24 18:36 to 20:22). Some runs may have seen older text. Either way, the pages cover the ask today.

### 2. Premise true? - premise_wrong
- The draft claimed the Beanie quickstart "never says why" and never says Motor is deprecated. In fact it says "not Motor" and explicitly tells Beanie 1 + Motor users to update. (The word "deprecated" is not used on the page, but the kit's connection skill does state the deprecation.)
- The draft claimed the agent found no Learn statement on `autoIndex` off in production or explicit index builds. The Mongoose tutorial states both.
- The draft's example pins `beanie==1.13.0` / `motor==3.1.2` were not found in the run folders. The pins actually found were beanie 1.16.4, 1.21.0 and 1.25.0, with motor 3.5.3 and 3.1.1. These were corrected above.
- Consistent with authoritative facts: Motor is deprecated in favor of PyMongo's async API, and vectors must be number[] for cosmosSearch indexes.

### 3. Maintainer skeptic - too_vague
As the Learn page owner, I would close this as already done: both pages contain the requested sections. What's left is generic ODM hygiene (projection with `.lean()`) plus a vector-typing note that belongs on the vector-search pages. Neither is concrete enough for an issue on these two pages.
